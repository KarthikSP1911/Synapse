# Mathz

Mathz is an adaptive mental-maths trainer. It drills four skills — **multiplication, percentages, fractions and squares** — in short sessions, records your accuracy and speed for every individual question, and steers practice toward what you find hardest and what is due for review.

## Features

- **Four skills**, each with its own setup, statistics and progress view: multiplication (1–20 tables), percentages, fractions and squares.
- **Session types** for every skill: fixed length (10, 20, 30, 50 or 100 questions), endless, and timed (30, 60 or 120 seconds). Timed sessions track a personal best per skill and length.
- **Focus**: an adaptive mix (default), only your weak questions, or only questions due for review.
- **Adaptive selection**: about 30% of questions (configurable) come from your weakest questions, weighted by weakness; due reviews are favoured next; recently asked and already-seen questions are avoided where alternatives exist. Unseen variations of a weak *concept* (for example another 25% question when 25% is your weak spot) are boosted too.
- **Spaced repetition**: one Leitner implementation shared by every skill (boxes 1–5, reviewed after 1, 2, 4, 8 and 16 days). Only unassisted correct answers advance a box; wrong, skipped, timed-out and hinted answers do not.
- **Hints, skip, pause/resume and an optional per-question time limit.** A correct answer after a hint counts as correct but does not advance the box. Pausing stops a timed session's clock.
- **Mistake review**: retry the misses of one session, or of the last 7 days, filtered by skill and exercise type. Original attempt history is never modified.
- **Worked explanations** after a miss, generated by deterministic rules (no AI service involved).
- **Progress dashboard** with a skill filter: accuracy and speed per skill and per exercise type, weak and mastered questions, weakest concepts, upcoming reviews, Leitner box counts, a trend chart, and (for squares) recall by number range.
- **Tables page**: the 20×20 multiplication heatmap, plus a separate 1–100 squares heatmap. Skills are never merged into one misleading heatmap.
- **Accounts**: sign up and log in with email and password. Every account has its own statistics, history and streak; "Remember me" keeps you signed in for 12 months. Practice requires an account. The first account to sign up inherits any data recorded before accounts existed.
- **Profile** (the user icon in the header): a year-long practice calendar heatmap (one square per day, darker for busier days), current and longest streak, active days, and a per-skill summary. Days follow the time zone your browser reports at login.
- **Settings** (stored in this browser): weak-question share, recent-question window, default difficulty, enabled exercise types per skill, default session length, per-question time limit, explanations, hints and live stats.
- **Keyboard-first** practice with visible focus rings, light/dark themes, and respect for `prefers-reduced-motion`.

## Skills and exercises

| Skill | Exercise types |
| --- | --- |
| Multiplication | `a × b` for any left and right numbers from 1 to 20 |
| Percentages | percent of a number · what percentage · increase / decrease (including "price rises from 80 to 100" and multi-step changes) · conversions between percentages, decimals and fractions |
| Fractions | simplify · fraction of a number · compare (which is larger, or greater / less / equal) · conversions between fractions, decimals and percentages |
| Squares | `n²` · `√n²` · missing value (`14 × 14 = ?`, `?² = 441`), with ranges 1–20, 1–50, 1–100 or any custom range within 1–100 |

Percentage and fraction practice have three **difficulty levels**:

- **Percentages** — *Beginner*: 1, 5, 10, 20, 25, 50, 75%. *Intermediate*: other whole-number percentages and bigger numbers. *Advanced*: decimal percentages (12.5%), percentages over 100 and multi-step changes. The range of numbers you take a percentage of is configurable (1–10,000).
- **Fractions** — difficulty controls numerator and denominator size and how tricky the simplifying is. Beginner "fraction of" questions always have whole-number results; advanced ones may need decimals. Conversions only use fractions with terminating decimals, because answers are checked exactly (see below).

## Getting started

### Prerequisites

- Node.js 20 or newer
- A Postgres database (a free Neon project works well)

### Setup

```bash
# 1. Install dependencies
npm install

# 2. Configure the database connection
cp .env.example .env.local     # then set DATABASE_URL

# 3. Create / upgrade the tables
npm run db:migrate             # existing databases: upgrades in place, keeps all data (adds accounts)
#    (a brand-new database can use `npm run db:push` instead)

# 4. Start the dev server
npm run dev
```

Open <http://localhost:3000>.

| `DATABASE_URL` | Postgres connection string used by the app and drizzle-kit |

## Upgrading an existing database

`npm run db:migrate` applies `src/db/migrations/0001_multi_skill.sql` in a single transaction. It is **additive and idempotent**:

- adds skill, focus, configuration, pause and per-question-limit columns to `practice_sessions`;
- adds skill, exercise type, stable question id, difficulty, prompt, answer text, outcome and hint columns to `question_attempts`, back-filled for every existing attempt (they were all multiplication), and makes the four multiplication-specific columns nullable (they stay filled for multiplication);
- creates `question_stats` and copies every row of `pair_statistics` into it (accuracy, streaks, weakness, Leitner box and due date), so multiplication history carries over;
- adds indexes. Nothing is dropped or rewritten, and running it again changes nothing.

`pair_statistics` is **no longer written** after the migration; it is kept so no data is lost and can be dropped later. `table_statistics` is still maintained for multiplication. Run the migration **before** starting the new code: the old code cannot insert attempts once the new NOT NULL columns exist, so any other deployment sharing the database needs to be redeployed at the same time.

## How it works

1. **Setup**: the home page shows the four skills with your progress. Choosing a skill shows only that skill's options. Starting creates a session (`POST /api/sessions`) storing the validated configuration.
2. **Pools**: a configuration defines a finite, deterministic **pool** of questions (`src/lib/skills/pools.ts`), filtered by difficulty tier and range, with every question parsed back through the id parser so it has an exact, sensible answer. Because pools are finite, the same question comes round again and its history accumulates.
3. **Ask**: `GET /api/sessions/:id/next` loads that skill's statistics and `selectNext` (`src/lib/selection.ts`) picks a question. The response contains the prompt and answer format, never the answer.
4. **Answer**: `POST /api/sessions/:id/attempt` sends the question id and the raw answer. The server **rebuilds the question from its id**, checks it belongs to the session, validates the answer, and records the attempt, the session totals, the question's statistics and its Leitner box.
5. **Review and report**: the summary, progress and tables pages read the stored data.

### Question ids and concepts

Every question has a stable id built from its operands, so the server can rebuild it and history attaches to it:

```
multiplication:12:8        percentage:of:25:80          percentage:what:15:60
percentage:change:increase:200:15   percentage:change:find:80:100   percentage:change:multi:200:10:-10
percentage:convert:d2p:0.75         fraction:simplify:12:16         fraction:of:3/4:80
fraction:compare:larger:3/4:2/3     fraction:convert:f2d:1/4        square:value:17   square:root:289
```

Related questions share a **concept** (`square:17` covers `17²`, `√289` and the missing-value forms; `percentage:pct:25` covers every 25% question; a fraction concept covers its simplify / of / convert forms). Concepts drive the "weakest concepts" view and the boost for unseen variations.

### Answer validation

Done on the server (and mirrored on the client only to disable *Submit* for malformed input). Numbers are compared as **exact rationals**, never floats, with no tolerance: `0.5`, `0.50` and `.5` are equal, `0.49` is not. A `%` is accepted only where the answer is a percentage. Fractions are `a/b` with optional spaces around the slash; equivalent fractions are accepted unless the exercise needs lowest terms (simplify, "convert to a simplified fraction"). Text that merely looks similar (`3/40` for `3/4`) is never matched by string comparison. Malformed input is rejected (HTTP 400) rather than marked wrong.

### Weakness score

Per question: starts from the error rate (`100 − accuracy`), adds 10 if the average response is slower than the skill's threshold (5 s for multiplication, 8 s squares, 10 s percentages, 12 s fractions), 10 per consecutive miss after the first, and 10 after a hinted answer; subtracts 20 after four unassisted correct answers in a row; clamped to 0–100. The multiplication formula is unchanged from earlier versions.

### API

| Method | Endpoint                    | Purpose                                                              |
| ------ | --------------------------- | -------------------------------------------------------------------- |
| POST   | `/api/sessions`             | Create a session (`fixed`, `endless`, `timed` or `review`)           |
| GET    | `/api/sessions/:id/next`    | Next question (`?exclude=<id>`), or `{ "finished": true }`           |
| POST   | `/api/sessions/:id/attempt` | `{ questionId, userAnswer, responseTimeMs, hinted?, outcome? }`      |
| POST   | `/api/sessions/:id/pause`   | Stop the session clock                                               |
| POST   | `/api/sessions/:id/resume`  | Restart it; paused time pushes a timed deadline back                 |
| POST   | `/api/sessions/:id/end`     | Mark a session as ended                                              |

`outcome` is `answered` (default), `skipped` or `timed_out`; a timeout is only accepted if the session has a per-question limit that really elapsed. The original multiplication payloads (`selectedLeftNumbers` / `selectedRightNumbers` to create a session, `{ left, right, userAnswer }` for an attempt) are still accepted. Errors are `{ "error": "..." }` with status 400 (invalid input), 404, 409 (session completed or paused) or 500.

## Testing

`npm test` runs 83 unit tests with no database: rational arithmetic, every spec example, question ids (round-trip and rejection of malformed ones), answer validation edge cases, difficulty-specific pool generation (every question in every pool is checked for tier, uniqueness and an exact answer), config and session-request validation, Leitner transitions and due dates, weakness scores, adaptive selection (rates, weighting, recent avoidance, fallbacks, focus modes), pause-aware timeouts, settings migration, and the square-range chart.

Not covered by automated tests: the SQL that updates session totals and the React components. During development these were exercised by hand against a development database (all four skills end to end: creating sessions, answering, skipping, hints, timeouts, pause/resume, mistake review, summary, progress and tables pages) and by `npm run build`, `npm run lint` and `npm run typecheck`; there is no committed end-to-end suite.

## Notes

- There is no authentication: statistics are shared by everyone using the same database.
- The app needs `DATABASE_URL` at runtime; pages that read statistics are rendered on demand, so builds do not need database access.
- Settings live in `localStorage`, so they are per browser.
